# review-bounded — 三轮有界代码审查 skill

[English](./README.md) | **中文版**

对当前分支改动执行三轮有界代码审查（Bounded Code Review）：固定严重度标尺（P0-P3）、每轮修复前征求授权、三轮后给出收敛判定——把"要不要继续 review"从无限循环变成数据决策。

## 解决的问题

```
"review一下当前改动" → 发现问题 123 → fix → 再 review → 又发现问题 456 → fix → 再 review → 又发现问题 789……
```

AI code review 没有"零问题"终点，但有收敛性：问题严重度随轮次递减。本 skill 在当前分支上执行**恰好三轮**的 review-and-fix，然后报告：

1. 每一轮发现了什么、改了什么，所有问题按同一标尺打 P0-P3；
2. 问题是否逐轮变弱（严重度趋势）；
3. fix 是否引入了新 bug（附证据）。

最后给出 **CONVERGED / NOT CONVERGED** 判定、检方陈述（反对合并的最强理由）和未修复项清单——让你知道什么时候该停。

## 工作方式

1. **第一轮**：审查基准分支（main/master）到当前工作区的差异，汇报问题（P0-P3），征求授权，在工作区修复（不提交），跑回归检查（有测试/lint 就跑）。
2. **第二轮**：重新读取最新代码（禁止凭记忆），优先看上一轮 fix 的增量和未覆盖的类别，与第一轮去重，然后同样的 汇报 → 授权 → 修复 → 验证 循环。
3. **第三轮**：同一循环，然后输出最终判定。全部修复均未提交，由你决定是否提交、如何提交（单 commit 或按 finding 分组）。

每一轮都通过 `git diff` 和重新读文件审查**实际最新代码**，绝不凭记忆重构。修复只改工作区、**过程中不提交**；最终判定后向你展示全部修复清单，由你决定是否提交及如何提交。轮次记录保存在对话内，**不产生额外文件**（用户要求留档时，agent 才把汇总写入 `REVIEW.md`）。

## 目录结构

```
SKILL.md                  # 编排核心：轮次循环 + 记录方式 + 铁律
references/
  rubric.md               # P0–P3 严重度标尺 + 审查类别清单（第一轮前加载）
  round-prompt.md         # 单轮指令：最新代码 / 去重 / 证据 / 授权 / 回归检查
  decision-rules.md       # 三轮后收敛判定规则 + 检方陈述 + 输出格式
```

## 设计原则

- **编排层，非执行层**：执行用 agent 原生工具（git、文件、Bash）和项目已有测试/lint；环境中若有其他审查 skill 可委托，否则用内置指令兜底。
- **零运行时**：纯 Markdown，无脚本、无依赖、无 API，可移植到所有支持 SKILL.md 标准的 agent（`npx skills add` 兼容）。
- **结构性约束写死**：第一轮前固定 rubric、每轮修复前征求授权、"不确定一律 NOT CONVERGED"、判定前先写检方陈述——这些不依赖模型自觉。
- **每轮都是新代码**：记忆永远不能替代读取仓库真实状态。

## 使用方式

- 按 agent skills 标准安装（发布后如 `npx skills add <owner>/review-bounded`），或直接放入你的 agent 的 skills 目录。
- 发起方式：`跑三轮 CR` / `对这个分支做有界 review`。
- 审查范围：当前分支与 main/master 的差异；在主分支上则为未提交改动。
